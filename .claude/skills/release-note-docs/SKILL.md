# Git 히스토리 간단 문서화

이 스킬은 Git 커밋 히스토리를 실용적이고 간결하게 문서화합니다.

## 핵심 작업 흐름

1. **날짜 범위 확인**
   - 시작일/종료일 확인 ("지난 주", "이번 달" 등 상대적 날짜도 처리)
   - 분석할 브랜치 확인 (기본값: 현재 브랜치)

2. **커밋 데이터 수집**
   ```bash
   # 기본 커밋 목록
   git log --since="시작일" --until="종료일" \
     --pretty=format:"%H|%an|%ad|%s" --date=short
   
   # 파일 변경 내역
   git log --since="시작일" --until="종료일" \
     --name-status --pretty=format:"%H|%s"
   ```

3. **변경사항 분석 및 그룹핑**
   - 커밋 메시지 분석하여 관련 기능끼리 그룹핑
   - 유사한 작업을 하나의 "주요 변경사항"으로 묶음
   - 각 기능과 관련된 파일 파악
   - 개발자별로 작업 내역 정리

4. **신규 기능 식별**
   - 커밋 메시지에서 "feat", "feature", "추가" 등 키워드로 신규 기능 찾기
   - 새로 생성된 파일(A) 확인
   - 이전 대비 추가된 기능 목록 작성

5. **템플릿 채우기**
   - `templates/commit_report_simple_ko.md` 로드
   - 분석한 데이터로 변수 치환
   - `release_note_YYYYMMDD_YYYYMMDD.md` 형식으로 저장

## 주요 Git 명령어

### 커밋 목록 가져오기
```bash
git log --since="2025-01-15" --until="2025-01-22" \
  --pretty=format:"%H|%an|%ad|%s" --date=short
```

### 파일 변경 상태 보기
```bash
git log --since="2025-01-15" --until="2025-01-22" \
  --name-status --pretty=format:"%H|%s"
```
- A: 추가된 파일
- M: 수정된 파일
- D: 삭제된 파일

### 특정 커밋의 변경 파일
```bash
git show --name-status --pretty=format:"" <commit-hash>
```

### 개발자별 커밋 수
```bash
git shortlog --since="2025-01-15" --until="2025-01-22" -sn
```

## 변경사항 그룹핑 전략

### 1. 커밋 메시지로 기능 파악
비슷한 키워드를 가진 커밋들을 하나의 기능으로 묶음:
- "로그인", "인증" → "인증 시스템 개선"
- "API", "엔드포인트" → "API 개발"
- "UI", "디자인" → "UI 개선"

### 2. 파일 경로로 모듈 파악
같은 디렉토리의 파일들을 하나의 모듈로 인식:
- `src/auth/*` → 인증 모듈
- `src/api/*` → API 모듈
- `tests/*` → 테스트 코드

### 3. 신규 기능 판별
다음 중 하나에 해당하면 "신규 기능":
- 커밋 메시지에 "feat:", "feature", "추가", "new" 포함
- 새로운 파일이 여러 개 생성됨 (A 상태)
- 새로운 디렉토리가 만들어짐

## 보고서 섹션별 작성 가이드

### 전체 요약
- 숫자만 간단히 표시
- 총 커밋 수, 참여 개발자, 변경 파일 수

### 주요 변경사항
- 커밋들을 2-5개의 큰 기능/주제로 그룹핑
- 각 그룹마다:
  - 기능 제목 (명확하고 간결하게)
  - 관련 커밋 해시 목록
  - 작업자 이름
  - 변경 내용을 2-3문장으로 요약
  - 관련 파일 목록 (주요 파일만)

### 커밋 상세 내역
- 날짜순으로 모든 커밋 나열
- 각 커밋마다:
  - 커밋 메시지
  - 짧은 해시
  - 작성자
  - 변경된 파일 목록
  - 1-2문장 변경 요약

### 개발자별 작업 내역
- 각 개발자가:
  - 몇 개 커밋했는지
  - 어떤 기능을 작업했는지
  - 주로 어떤 파일을 수정했는지

### 신규 기능
- 이전 대비 새로 추가된 기능만
- 간결하게 1줄로 설명
- 추가된 파일과 담당자 표시

## 파일명 규칙

`release_note_YYYYMMDD_YYYYMMDD.md`

예시:
- `release_note_20250115_20250122.md`
- `release_note_20250101_20250131.md`

## 실용 팁

### 커밋 메시지 패턴 인식
자동으로 다음을 인식하여 그룹핑:
- `feat:`, `feature:` → 신규 기능
- `fix:`, `bugfix:` → 버그 수정
- `refactor:` → 리팩토링
- `docs:` → 문서 작업
- `test:` → 테스트 추가

### 중요 파일 우선 표시
다음 파일들은 중요하므로 우선 표시:
- `src/` 하위의 주요 코드 파일
- 새로 생성된 파일
- 변경 횟수가 많은 파일

### 너무 많은 커밋 처리
- 커밋이 50개 이상이면 주요 변경사항만 간추려서 표시
- 자잘한 커밋은 "기타 수정사항"으로 통합
